# Agent 笔记：首管理员先消费令牌再标记初始化

状态：已实现

## 先说结论

在空库上注册首管理员时，服务在一个事务里先消费初始化令牌，再写入管理员已初始化标记。两次更新都检查影响行数。

## 问题

令牌消费 SQL 限定管理员尚未初始化。更新顺序颠倒时，令牌有效也会因影响行数为零而回滚，导致干净安装无法登录。历史部署材料在 11 月 9 日记录了此问题，11 月 12 日在当前实现修复并复验。

## 决策

保留初始化记录的行锁和事务边界。在获取该行后验证令牌，消费成功才标记初始化并完成注册。任何竞争失败均按原事务回滚。

## 考虑过的备选方案

移除消费 SQL 的未初始化判定会放宽并发时的限制。只改测试数据会掩盖空库安装的实际失败。

## 后果

全新安装支持一次成功注册。重复尝试不能重新获取管理员身份。

## 验证

运行 UserServiceTests 检查两次更新的顺序；[双机验收](../../../../docs/logs/20261112-中控与内网节点作业双机验收.md)包含从空库注册并登录。

## 适用范围

适用于 Java 中控初始化和以空库启动的安装验收。
