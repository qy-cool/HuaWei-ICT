# Agent 笔记：企业项目的成员与节点访问范围

状态：已实现

## 先说结论

项目所有者管理成员，平台管理员把节点分配给项目环境。项目的开发与测试环境可以接收测试作业。升级现有安装时先复核旧节点归属。

## 问题

原管理接口以企业全局节点目录工作，成员分组后仍须处理旧监控订阅和既有客户端。

## 决策

项目查询与作业接口校验用户所属项目；同一节点同时只分配给一个项目环境。历史节点迁入单独项目的生产环境，管理员按实际用途重新分配。企业安装模板启用 PROJECT_ISOLATION_ENABLED，将全局管理和旧 Monitor 订阅限制给管理员，并周期复核已建立订阅。无 SSH 的节点通过短时登记令牌兑换独立身份。

## 考虑过的备选方案

自动依据节点名称推断项目会把历史机器错误授权给成员。直接移除旧入口会破坏仍依赖全局监控的既有客户端。

## 后果

管理员可以保留旧监控工具。升级时需要明确调整环境开关、成员和节点，普通成员使用项目范围的接口。

## 验证

ProjectFlowTests 覆盖成员权限和节点归属，ProjectIsolationMonitorTests 核对旧订阅权限，[双机验收](../../../../docs/logs/20261112-中控与内网节点作业双机验收.md)覆盖一次性节点登记及测试节点分配。

## 适用范围

适用于从 V37 升级的原部署、独立自托管的新安装、节点登记与按项目授权的 API。
