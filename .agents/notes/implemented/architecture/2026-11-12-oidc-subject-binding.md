# Agent 笔记：企业身份与平台账号的绑定

状态：已实现

## 先说结论

企业登录使用管理员预登记的发行方和大小写敏感的 subject 查找本地账号。密码登录和企业登录共用账号审核、角色检查及平台 JWT 签发。管理员可以在身份服务故障时使用原登录入口恢复配置。

## 问题

企业的邮箱、显示名和目录组均可能变化。本地账号已经拥有项目、节点及环境的明确授权，需要保持这些授权与账号的对应关系。

## 决策

企业登录采用授权码流程、S256 PKCE 和五分钟浏览器绑定。数据库仅保存 state、nonce 与 verifier 摘要，换取身份之前按事务消费一次性登录状态。登录只信任管理员配置的端点，以发行方、受众、签名、nonce、有效时间和已登记映射共同判定。

## 考虑过的备选方案

按邮件匹配已有用户会把企业身份绑定到可变字段。自动从目录组产生平台权限需要定义独立的同步、撤权与审计契约，现阶段使用本地审核和项目成员表。

## 后果

企业用户能够通过统一身份服务访问既有项目。管理员需要维护身份映射，企业更换发行方时需要重新登记账号。撤销身份映射影响新的企业登录，已签发会话遵循现有的平台撤销策略。

## 验证

运行 `node scripts/check-openapi.mjs` 核对接口，并按[OIDC 管理手册](../../../../docs/ops-manual/企业OIDC登录.md)运行回环身份服务、真实 Java 和 MySQL 的登录与撤销验收。

## 适用范围

适用于 `server/src/main/java/cloide/server/module/auth/oidc/` 及[企业登录契约](../../../../docs/openapi/openapi-oidc.json)。
