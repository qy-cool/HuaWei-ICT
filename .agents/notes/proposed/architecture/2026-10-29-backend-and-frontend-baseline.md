# Agent 笔记：后端升级候选与历史前端技术基线

状态：提议中

## 先说结论

本阶段在现有 Java 21、Spring Boot 3.4.13、MyBatis-Plus 3.5.12、springdoc 2.8.9 上完成后端收口。2026-10-29 的 Boot 4 组合和 React 19 等属于历史候选。用户将在后续独立选择管理前端框架。

## 问题

最小样例的通过能证明一组库可以启动，但现有生产接口还需要兼容数据库升级、认证、消息序列化、旧 Agent 和 Android。把早期前端候选写成当前交付要求，会让后端发行依赖尚未选定的工具。

## 提案

保留对 Spring Boot 4.1.2、MyBatis-Plus 3.5.18、springdoc 3.2.0 的升级评估。待独立安排升级时，在同一候选环境评估上下文启动、数据库读写、接口契约生成及已有客户端兼容性。当前运行组合以 [Maven 配置](../../../../server/pom.xml) 为准。

早期 React 19、Vite、Base UI、TanStack 等候选仅作为技术调研记录。管理客户端可通过 REST 与 WebSocket 契约自行实现。前端框架、依赖和开发工作由用户后续决定。

## 考虑过的备选方案

历史提案也曾考虑 Spring Boot 3.5.16 或 4.0.x。各组合需要核对其受支持版本、依赖兼容性和实际迁移成本。直接替换当前栈会同时改变 Spring、JSON 解析、数据库访问与接口描述，故需独立验收。

## 验收标准

后端候选应通过既有应用测试、旧库迁移及旧客户端契约测试。升级 OpenAPI 规范时核对真实输出、必填与可空字段、错误语义，并记录发现的兼容差异。本阶段验收只针对已写好的后端、节点和相关运行材料。

## 风险

Jackson、MyBatis 和云 SDK 的集成行为需利用实际工程测试。最小样例不会涵盖所有模块的运行行为。原始组件选型文档继续作为历史决策依据。

## 验证

2026-10-29 曾以 Boot 4 最小样例运行 3 项测试并观察到 OpenAPI 3.1.0 输出。当前后端从仓库根执行下列检查。已有 Java、Go 与迁移的验收记录见[后端实施与验证](../../../../docs/logs/20261112-企业平台实施与验证.md)。

```sh
(cd server && bash mvnw -B -ntp test)
node scripts/check-openapi.mjs
```
