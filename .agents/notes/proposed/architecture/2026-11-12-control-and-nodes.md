# Agent 笔记：中控与企业节点的职责

状态：提议中

## 先说结论

中控已承担项目授权与作业记录，开发节点已能通过主动连接承担浏览器工作区、隔离测试和制品回传。本提案保留完整企业拓扑的验收标准，包括应用与中间件分机运行，以及独立中控故障域的接管和恢复。

## 问题

节点能访问中控，仍可能无法用业务身份连接数据库、缓存或队列。一次中控进程接管成功，也不足以说明共享数据库、制品存储和工作区入口在整台机器失效时仍可用。

## 提案

延续 Java 模块化中控和独立平台 MySQL，将服务放置关系绑定到项目环境与节点。调度测试前检查节点能力与项目授权，发布前从实际应用节点检查服务认证及读写。业务数据库由企业按实际拓扑分配。把连接登记、工作区转发和共享制品分别纳入多中控接管验收。

## 考虑过的备选方案

在中控编译全部项目会让企业代码与管理凭据共享机器，也会挤占管理端资源。按每个技术模块拆分中控进程会增加早期安装、升级及协调租约的成本。

## 验收标准

已有记录覆盖无 SSH 凭据登记、项目分配、两机仓库测试和同机第二个中控进程接管。历史浏览器夹具验证了 ARM64 工作区编辑、休眠恢复、撤权后断开两条现有连接。[项目授权决策](../../implemented/architecture/2026-11-12-project-access-boundary.md) · [作业对账决策](../../implemented/architecture/2026-11-12-durable-node-jobs.md) · [工作区实测](../../../../docs/logs/20261112-浏览器云IDE双机验收.md)

完整拓扑需分别保留三份实测记录。第一份从应用机证明数据库、缓存、消息认证及读写。第二份在管理面断开时持续提交订单，再核对恢复连接后的订单与节点实际版本。第三份停止整台活动中控，在独立机器重新取得制品、工作区路由和原作业，并核对被撤销的会话。

## 风险

测试环境和生产环境可能是同一物理机上的不同身份。发行说明应同时列出逻辑身份数、机器数、共享存储与网络条件，以便企业判断哪些故障已经演练。

## 验证

从仓库根复现已测的跨进程接管部分。两个别名指向获授权的隔离联调机，JAR 与 Agent 应来自同一候选版。[复现条件与实测范围](../../../../docs/logs/20261112-中控跨JVM作业接管.md)
