# 统一代码审查政策

请严格结合需求、目标分支和实际改动进行判断。

## 核心检查

1. 先确认变更是否满足关联 Issue、开发计划（`docs/plans/`）
   或明确需求。没有关联时跳过完成度判断；只实现部分内容时，明确已完成
   和未完成范围。
2. 判断问题是否由本次变更引入或明显加剧。非本次变更引入、且未被本次
   改动实质恶化的问题，不要求当前变更修复。
3. 检查是否符合现有架构、命名、风格、错误处理和模块边界（相关
   `hwict-*` skill）。
4. 检查日志是否覆盖关键流程、异常分支和失败场景，是否有可关联的上下文；
   不得输出密码、Token、SSH 私钥、完整机器路径或环境内容。
5. 检查错误处理、边界条件、并发安全、取消、资源清理、兼容性和可测试性。
6. 评估职责是否清晰，是否新增隐式耦合、重复实现、难以测试的结构或整体
   重写风险。
7. 避免过度抽象和无必要依赖。新增抽象必须服务于明确复用、跨端一致性或
   职责边界。
8. 检查新增文件的命名、目录归属和职责，避免单个文件职责过多或放置位置
   与同类文件明显不一致。
9. 只检查本次新增或显著扩大的文件、目录规模问题。拆分建议必须基于明确
   职责边界和维护收益，不得为了降低行数机械拆分。
10. 跨端共享的确定性行为优先沉淀到明确的共享层（如后端统一契约与工具），
    再由各端接入；端特有能力留在对应端。只有确实共享语义时才提出下沉，
    不得借 Review 要求无关的历史重构。
11. 检查新增行为、失败场景、边界条件和跨端契约是否有必要的测试、契约
    文档和验证。不要为了形式完整增加与本次变更无关的内容。
12. 问题必须有明确触发条件、实际影响和合理复现路径。无法稳定复现或只是
    主观偏好时，不得列为阻塞问题。
13. 所有结构、质量和可维护性问题，都必须先确认由本次变更引入或加剧。
14. 检查本次变更是否改变了架构边界、共享契约、安全策略、测试策略或部署
    流程。如果改变，必须确认相关决策笔记（`.agents/notes/`）是否需要同步
    更新；长期决策应迁入 `.agents/notes/implemented/`，`docs/` 保留
    教程、契约、手册与交接材料。

## 成熟能力复用审查

当改动新增或扩大工具类能力（加解密、重试、限流、审批流、报表、日期处理、
HTTP 客户端封装等）时，必须检查：

1. 项目已选型或已引入的依赖（当前基线：Spring 生态、MyBatis-Plus、
   shadcn/ui、TanStack 系列、ECharts 等）或官方扩展点是否已提供该能力。
2. 是否有证据表明升级依赖或使用扩展点仍无法满足明确需求，而不是为了
   绕过暂时的集成困难建立长期平行实现。
3. 新实现是否只拥有编排、配置、资源预算与用户体验，把领域事实保留在
   成熟实现中。
4. 是否因"两端都要用"而把同一语义在后端、前端、Agent 各实现一遍。跨端
   要求的是稳定契约，不是三份拷贝。
5. 部分复用是否覆盖完整用户链路和状态一致性，而不是只验证单个函数的
   返回值。
6. 如果确需自研，相关决策笔记是否记录了依赖版本与能力、许可限制、
   功能缺口、被否复用方案及未来的删除或迁移条件。

新增平行实现而没有上述证据时，不得仅以"更可控""以后可能需要""跨端"
或"接入麻烦"作为理由。将它报告为重复实现与双重真源问题；仅在有明确可
复现的正确性、兼容性或资源回归时按 P1 报告，否则按 P2 报告并要求补齐
复用证据和长期所有权决策。

## HuaWei-ICT 特别边界

- 后端工程固定为 `server/`，包结构 `cloide.server/`
  下按 config/common/security/module/client 分层；业务模块在 `module/`
  下按 controller/service/mapper/entity/dto/vo 组织。
- Go Agent 固定为 `agent/`：不持有数据库凭据；只通过环境变量读取后端地址
  与 Agent Token；Linux PTY 与命令执行默认关闭。
- Android 固定为 `android/`：不硬编码后端地址；release 构建必须通过
  `-PBASE_URL` / `-PWS_URL` 注入；keystore 不入库。
- **OpenAPI JSON（`docs/openapi/`）是 REST 契约唯一事实源**：
  改接口必须同步契约，前端 `src/types/<module>.ts` 类型定义与之对齐
  （细则见 `hwict-react`）。
- WebSocket / SSE 消息契约以 `docs/protocol/` 冻结文档为准；改消息结构
  必须同步协议文档并评估对已有调用方的兼容性。
- 安全敏感区：JWT 配置与密钥管理、华为云 AK/SK 与 MaaS API Key 的读取
  路径、admin 角色校验、日志脱敏与提示词注入防护。涉及这些区域的改动
  默认提高一级审查严格度。
- **已执行到任何共享环境的 Flyway 迁移脚本不得修改**，只能新增版本脚本。
- 前端 HTTP 调用统一走 `src/lib/` 中的请求封装（见 `hwict-react`），
  不得在组件里散落直连后端。
- 架构取舍与高风险约束以 `.agents/notes/implemented/` 为准。
- 测试问题必须结合 `hwict-tests` 规则判断，重点关注有界等待、
  确定性时间、取消和清理。
- 只有当行为或契约确实改变时，才要求更新决策笔记、契约文档或协议文档。
- 如果相关笔记的适用范围、路径、验证命令或决策内容已失效，必须建议更新
  原笔记，或在新决策取代旧决策时迁移到 `archived/`。

## 需求与范围判断

- 多个需求时逐个判断，并说明各自完成度。
- 没有可访问的 Issue 或计划时写明"未找到可验证的关联需求"，不得虚构。
- PR / 提交描述不能替代实际证据；以变更、调用链、测试和已有验证结果为据。
- 将每个问题标记为"本次引入""本次加剧""历史问题"或"未确认"。
  只有前两类可以进入 Findings。
- 如果 base/head、变更清单、关键调用链或验证信息不完整，结论写"信息
  不足"，不要用猜测补全。
