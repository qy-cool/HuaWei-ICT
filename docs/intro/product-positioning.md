# 产品定位与价值

2026-11-20。本文是 Cloide（仓库标识 HuaWei-ICT）的产品定位主线，说明要做成什么样的企业级平台、为谁解决什么问题、哪些能力已有实测证据。赛事材料如需引用这些事实，见 [docs/competition/](../competition/README.md)；赛程与评分点不改变本文的目标与边界。

## 1. 我们要做成什么

目标是建设一套**完整的、可长期维护的企业级自托管 AI 软件工程平台**：企业独立部署一套中控，管理多个项目、环境与 Linux 节点；开发者通过项目 API 和浏览器工作区工作；AI 在授权范围内参与编码、测试、发布与维护。

平台要对软件从需求到运行的过程负责。一条工程任务应能回答六个问题：谁提出了什么需求，AI 改了哪些代码，哪些测试实际通过，哪个制品部署到了哪些机器，发布后发生了什么，如何恢复到上一健康状态。

本项目不按赛程、评分点或某次参赛要求压缩或绑死架构与路线图。近期开发顺序仍以[现状盘点与下一轮开发计划](../plans/20261112-现状盘点与下一轮开发计划.md)中的 A1–A5 为先，不另定赛事驱动的时间表。管理台 Web 前端框架仍由项目负责人选定，本轮不启动 `web/` 实现。

## 2. 业务痛点

企业引入 AI 编码工具时，常见的三个障碍是：

1. **不可控。** AI 改了什么代码、跑了什么测试、动没动生产环境，团队说不清。许多商业工具的操作日志不在企业手里。
2. **不可信。** AI 说「已完成」不等于工程上完成——测试是否真实通过、制品从哪个提交构建、发布后能否回滚，缺少可审计的证据链。
3. **数据不出域。** 企业代码、凭据与模型调用往往有数据主权要求。公有 SaaS 难以完全满足；纯内网方案又可能缺少企业想用的模型或基础设施能力。平台应让企业把控制面留在自托管边界内，同时按需接入选定的模型与云服务。

## 3. 方案定位

**企业自托管的 AI 软件工程平台**（产品名 Cloide）：

- 一套中控管理多个项目、环境与服务器；开发者可在浏览器工作区工作，也可通过项目 API 提交与查询作业；
- AI 在授权范围内编写代码、执行测试、参与发布与维护：自主程度分三档（变更前确认 / 自主模式 / 完全访问）并另设独立计划模式，授权沿「用户 → 项目 → 环境 → 节点/服务 → 动作」逐层收敛；
- 业务应用与中间件运行在企业指定的节点（内网节点主动连接中控）；
- **平台与具体云厂商、模型提供商解耦。** 企业可按需求选择部署位置，并替换模型端点、身份提供方、存储、队列等基础设施。华为云是可选的部署与集成方案，也是当前的试验环境之一，不是「全部模型与基础设施必须使用华为云产品」。选项与现状见[部署与基础设施选项](../tech-summary/deployment-options.md)。

## 4. 用户价值

| 用户 | 得到什么 | 现状边界 |
|---|---|---|
| 开发者 | 浏览器云 IDE 与 AI 结对：AI 提计划、改代码，人工逐项审批或授权自主执行，自己的未提交改动应被保留 | 云 IDE 与编码链路已在受控环境验收；模型目前多用回环或节点本地配置，真实企业模型质量待测 |
| 项目负责人 | 审批绑定具体变更（制品摘要、目标环境、配置版本），换包或换目标后应失效重审 | 编码任务与发布链已有相应验收；管理台页面待建，当前以 API 为交付入口 |
| 运维 | 告警可关联最近发布，并能回查提交、测试报告与负责节点；中间件与控制面备份恢复有演练记录 | 演练规模与拓扑见日志；跨故障域与生产规模恢复仍待做 |
| 企业 | 代码、凭据与审计数据留在自托管边界内；模型与云服务由企业自行选择 | 华为云 MaaS 等托管模型服务尚未接入真实端点，不能写成已经提供的能力 |

## 5. 长期工程方向

下面是产品需要持续满足的工程方向，用验收维度表达，不作为已全部完成的声明，也不另定日历。已有实现与缺口以[实施与验证记录](../logs/20261112-企业平台实施与验证.md)和 A1–A5 队列为准。

| 方向 | 含义 | 当前能核对到的事实 |
|---|---|---|
| 安全与权限隔离 | 授权可收敛到项目、环境、节点/服务与动作；越权不泄露其他项目的存在性 | 已有项目隔离、审批与撤权等验证；真实企业 IdP 与跨项目入口的端到端验收仍待完成（A5 等） |
| 审计 | 关键操作可追溯到人、变更、制品与环境 | 已有审计与证据链方向的实现和记录，范围随功能继续补齐 |
| 可观测性 | 运行状态、告警与最近发布可互查 | 已有监控、告警及与发布的关联；企业安装的域名、证书与网络由安装方配置 |
| 备份恢复 | 控制面与业务中间件都能恢复到可核验的新实例 | 已有控制面与 PostgreSQL/Redis/RabbitMQ 演练记录；跨故障域与生产规模另测 |
| 升级兼容 | 已执行的数据库迁移不被改写；升级与回滚路径可复现 | Flyway 只新增版本；稳定发行与跨版本升级见长期维护阶段，尚未作为已完成交付 |
| 测试与发布 | 测试通过、制品来源与环境提升可核验，坏版本可回滚 | 签名制品、测试到生产提升与数据回退已有双机记录 |
| 运维维护 | 安装、升级、值班与故障处理有可执行手册 | 已有工作台接入、恢复与中间件手册；随版本持续维护 |

## 7. 与已有方案的差异

详见[创新性](../tech-summary/innovation.md)。一句话：许多工具解决「AI 会写代码」，本项目要解决「企业敢让 AI 写代码」——权限收敛、逐次审批、幂等与证据链是承重墙，而不是附加功能。
