# 工程 API 与节点接入

安装者可以用 HTTP 客户端完成项目登记、派发节点作业和查询结果。本轮交付以中控 API、节点协议和后端测试为准。平台管理台的框架由项目负责人选定。早期临时客户端曾用于浏览器联调，记录保留在[双机验收日志](../logs/20261112-中控与内网节点作业双机验收.md)。

## 接入中控与注册节点

1. 安装 Java 中控和 MySQL，数据库账户需具备 Flyway 迁移权限。配置 JWT、凭据加密密钥和首管理员初始化令牌，在 HTTPS 网关暴露项目 API。企业多项目部署在所有中控设置 `PROJECT_ISOLATION_ENABLED=true`。[安装手册](cloide-shell-Server-部署安装手册.md)
2. 空库通过 `POST /api/auth/register` 携一次性初始化令牌注册首管理员。后续成员注册后由管理员审核。`POST /api/auth/login` 返回登录令牌，项目 API 使用 `Authorization: Bearer <JWT>`。通过 `POST /api/projects` 建立项目，保存返回的项目 ID。创建者为 owner，项目负责人或平台管理员管理该项目成员。[认证契约](../openapi/openapi-auth.json) · [项目契约](../openapi/openapi-project.json)
3. 平台管理员以自己的 JWT 调用 `POST /api/admin/node-enrollments`，请求体可用 `{"name":"开发节点"}`。将有效期十分钟的 `data.ticket` 交给目标节点安装者。在 Linux 私有配置目录内，以运行 Agent 的账户执行 `python3 deploy/agent/enroll.py https://SERVER_IP_OR_DOMAIN ./agent.env`，按提示输入票据。脚本验证 TLS、生成私有配置并输出节点 ID。节点以 WSS 主动出站，令牌登记支持无 SSH 凭据的机器。[登记契约](../openapi/openapi-enrollment.json)
4. 平台管理员调用 `PUT /api/projects/{projectId}/environments/{environment}/nodes/{serverId}` 分配节点。dev 和 test 环境的节点可执行项目测试。Linux 构建节点使用专用非 root 账户，配置本地只读裸仓库、离线工具链和测试命令。通过 `GET /api/projects/{projectId}/nodes/{serverId}/capabilities` 查看它已上报的架构和该项目允许使用的仓库。[节点作业协议](../protocol/node-jobs-v1.md)

## 从 API 验收一次真实测试

对已分配的 dev 或 test 节点，以项目开发者、负责人或平台管理员身份调用 `POST /api/projects/{projectId}/runs`。将下例节点和示例 SHA 替换为清单内的节点及其裸仓库中真实存在的提交。为一次新运行生成一个请求 UUID。

```json
{
  "request_id": "cdf05e51-a0f8-4d1a-b219-2307eb09ee24",
  "server_id": 7,
  "repository": "orders",
  "commit_sha": "0123456789abcdef0123456789abcdef01234567"
}
```

从响应记录 `data.job_id`。通过 `GET /api/projects/{projectId}/runs/{jobId}` 查看 `status`、`commit_sha`、`exit_code` 和最终输出。通过同一路径下的 `/logs?after=0` 读取日志，记录每段的 `seq`，后续将最后收到的序号作为 `after`。请求意外中断时，以相同 `request_id` 和相同字段重试。节点失联后继续查询原作业。遇到 `uncertain` 时先核对节点持久记录与实际效果，再决定是否发起新的运行。[作业契约](../openapi/openapi-job.json)

集成验收核对请求身份、目标节点、SHA、同一作业号、实际退出码和持久日志。在专用环境丢弃一次终态确认，检查重连前后的内容相同、节点仅执行一次。完成后清理临时进程、目录与凭据。采用既有双机脚本的 API 路径可独立复跑，历史 Edge 客户端用例另有记录。[双机复跑说明](../../scripts/api-test/README.md) · [跨 JVM 接管记录](../logs/20261112-中控跨JVM作业接管.md)

## 从仓库到发布怎样交接

| 负责角色 | 接口或节点动作 | 需要核对的证据 |
|---|---|---|
| 平台管理员、节点管理员 | 平台管理员通过项目下的 `/repositories/import` 导入或 `/repositories` 从企业模板新建。节点管理员同步只读 Git 对象库并配置受信任分支、仓库别名和工具链。 | 保存远端仓库 ID、默认分支和节点实际存在的 SHA。登记仓库后仍需单独准备节点源码。[GitHub 接入](../ops/github-app-repositories.md) |
| 工作区所有者 | 从项目工作区 `/workspaces/{id}/tickets` 获取一次性票据，经独立工作区域名访问 code-server。受管实例的 `/sleep` 和 `/wake` 接口返回期望状态，随后核对节点观测。 | 确认休眠恢复后未提交文件可读，撤权关闭现有连接。双机曾使用真实 code-server 和 Edge 验证编辑、终端与撤权。该能力可独立于平台管理台接入。[网关手册](../../deploy/workspace/README.md) · [双机记录](../logs/20261112-浏览器云IDE双机验收.md) |
| 开发者、编码节点管理员 | 开发者向项目的 `/coding-tasks` 提交需求、仓库、基准 SHA、执行模式和计划开关。模型、端点、凭据及可访问文件由编码节点管理员在项目策略与节点配置中指定。通过任务详情、事件和审批接口核对差异，待审查任务可用仓库的 PR 接口提交。 | 保存任务 ID、基准提交、修改内容摘要、审批和远端 PR 提交。合并后选定实际提交，另外运行节点测试。[编码 API](../openapi/openapi-coding.json) · [Pi 节点](../../worker/README.md) |
| 构建节点管理员 | 为仓库配置制品类型，隔离构建写入指定输出，宿主上传器携该节点凭据向中控登记。 | 核对来源节点、成功作业、提交、类型、SHA-256 和下载字节。丢失确认后重复上传同一制品。[构建制品契约](../openapi/openapi-build.json) |
| 发布负责人、平台管理员 | 在项目环境的 `/releases` 提交服务、目标和制品，查询代次、节点回执和探针。生产提升要求平台管理员、构建节点来源和该制品在测试环境同服务的健康记录。 | 从测试和生产的健康记录核对同一摘要、实际活动版本及回滚结果。安装方管理发布私钥和签名投送。[发布 API](../openapi/openapi-release.json) · [节点执行器](../../deploy/release/README.md) |
| 值班人员 | 查询项目运维 API 中的告警、关联节点与发布，按授权记录原因、申请回滚或创建修复任务。 | 分别核对服务恢复和业务数据恢复。有状态服务在新实例验证，再由业务负责人决定切换。[运维 API](../openapi/openapi-operations.json) · [中间件恢复](../../deploy/middleware/README.md) · [中控灾备](../../deploy/recovery/README.md) |

新建仓库与导入已有仓库应分别完成同一项订单需求，再比较两条路径留下的提交、测试、制品、发布和业务核对记录。尚待连接的步骤、依赖和验收条件列在[下一轮开发计划](../plans/20261112-现状盘点与下一轮开发计划.md)。
