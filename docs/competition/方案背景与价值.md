# 方案背景与价值（初赛素材初稿）

2026-11-19。初赛五要素「方案背景与价值」的素材初稿，数字与证据以
`docs/logs/` 的实测记录为准（全量测试数取最近一次全量回归），不写无依据
的估计。定稿时按官方模板重排。

## 1. 赛题理解

赛题要求基于华为云产品打造 AI 创新应用。本项目的回答是一个「AI 软件工程
平台」：让 AI 真正进入企业的开发、测试、发布与运维全流程，而不是停留在
聊天式代码补全。

## 2. 业务痛点

企业引入 AI 编码工具的三个现实障碍：

1. **不可控**。AI 改了什么代码、跑了什么测试、动没动生产环境，团队说不清。
   商业 AI 编码工具的操作日志不在企业手里。
2. **不可信**。AI 说「已完成」不等于工程上完成——测试是否真实通过、制品
   从哪个提交构建、发布后能否回滚，缺乏可审计的证据链。
3. **数据不出域**。企业代码、凭据与模型调用的数据主权要求高，公有 SaaS
   工具难以满足，而纯内网方案又缺少云上的模型与基础设施能力。

## 3. 方案定位

**部署在华为云上的企业自托管 AI 软件工程平台**（产品名 Cloide）：

- 一套中控管理多个项目、环境与服务器；开发者在浏览器里工作；
- AI 在授权范围内编写代码、执行测试、发布与维护：自主程度分三档
  （变更前确认 / 自主模式 / 完全访问）并另设独立计划模式，授权沿
  「用户 → 项目 → 环境 → 节点/服务 → 动作」逐层收敛；
- 业务应用与中间件运行在企业指定的子服务器（内网节点主动连接公网中控）；
- 模型与基础设施底座全部使用华为云产品（见
  [华为云产品映射](huawei-cloud-mapping.md)）。

平台对软件全生命周期负责，一条工程任务能回答六个问题：谁提出了什么需求，
AI 改了哪些代码，哪些测试实际通过，哪个制品部署到了哪些机器，发布后发生
了什么，如何恢复到上一健康状态。

## 4. 用户价值

| 用户 | 得到什么 |
|---|---|
| 开发者 | 浏览器云 IDE + AI 结对：AI 提计划、改代码，人工逐项审批或授权自主执行，自己的未提交改动始终保留 |
| 项目负责人 | 审批绑定具体变更（制品摘要、目标环境、配置版本），换包/换目标自动失效重审 |
| 运维 | 告警关联最近发布，可从告警回查提交、测试报告与负责节点；中间件备份恢复有实测记录 |
| 企业 | 代码、凭据、审计数据留在自托管边界内；模型能力来自华为云 MaaS |

## 6. 与已有方案的差异

详见[创新性解读](innovation.md)（另稿）。一句话：现有工具解决「AI 会写
代码」，本项目解决「企业敢让 AI 写代码」——权限收敛、逐次审批、幂等与
证据链是承重墙，而不是附加功能。
