# 数据集与评测设计（提案稿）

2026-11-26。**本文是提案稿，尚未经队长确认；确认并按需修订后，才成为仓库的成文评测方案。**在此之前，任何「订单工程评测任务集」都不得在其他材料中被引用为已有共识。

对应初赛五要素中「数据集选取与处理」。评测对象是平台的 AI 编码任务能力；平台本身的工程可靠性证据不依赖本设计，见[产品定位第 6 节](../intro/product-positioning.md)。

## 1. 设计原则

- **载体用现成参考工程**：评测在[订单系统回归工程](../../examples/orders/README.md)上进行。它已包含 Spring Boot API、PostgreSQL 订单数据、Redis 版本化缓存与 RabbitMQ 订单事件，且业务核验语义在仓库内有明确记载。
- **数据全部自建合成**：订单数据由评测脚本按固定种子生成，不使用任何外部语料或用户数据，**不存在数据来源与授权问题**。这也意味着「数据来源与授权」这一评分要素对本项目是最简项。
- **可复现优先**：每个任务的输入（需求文本、基准提交、初始数据集）都固定为可重放的形态；模型侧先用回环服务做确定性回归，真实模型端点接入后再采集效果数据。
- **不预设任务数量**：任务集规模待队长确认后定稿。本文只定义任务类型的划分方法与每类的判据。

## 2. 任务类型（基于 orders 既有核验场景设计）

以下四类是**基于订单工程 README 已记载的业务核验场景设计**的任务类型划分，不是 README 已定义的分类。README 提供的是核验语义，任务集由本设计在其上构造。

| 类型 | 设计依据（orders README 已有核验语义） | 任务示例形态 | 判据 |
|---|---|---|---|
| T1 业务功能 | 订单创建、取消流程的完整语义 | 为未发货订单增加取消功能并补测试 | 单测/集成测试真实通过；差异可审查 |
| T2 边界与并发 | 重复取消保持版本；已发货取消返回 409 | 构造重复取消、非法状态迁移用例 | 边界行为与 README 语义一致；不引入回归 |
| T3 缓存一致性 | 同订单 ID 与版本号的缓存核对；读详情后检查版本化缓存 | 修改订单后验证缓存失效与回源路径 | 缓存版本与库内一致；命中/回源行为正确 |
| T4 消息幂等 | 消费者按事件 ID 去重；恢复后核对回执唯一条数 | 重复投递场景下验证消费幂等 | 重复投递不产生重复业务效果；回执条数唯一 |

每个任务交付物固定为：需求文本、基准提交 SHA、AI 产生的补丁、真实测试报告、审批记录。这些字段与[编码任务端到端验收](../logs/20261112-编码任务端到端验收.md)中已有的验收链一致，不另造格式。

## 3. 指标口径（待真实模型端点接入后采集）

| 指标 | 定义 | 采集方式 |
|---|---|---|
| 任务完成率 | 终态为可审查补丁的任务占比 | 任务记录统计 |
| 测试通过率 | AI 补丁在真实测试节点的通过比例 | 测试报告回读 |
| 人工干预次数 | 从任务创建到终态期间的人工审批与修正次数 | 审批记录统计 |
| token 用量 | 每任务模型调用消耗 | 模型网关/回环服务计量 |
| 恢复动作数 | 任务异常（超时、断线）后的恢复步骤数 | 事件日志统计 |

以上均为**口径定义，尚无实测数值**。回环模型只验证链路确定性，不产出效果结论；效果数据待真实模型端点接入后采集，届时在 `docs/logs/` 落记录并回填[可量化效果](可量化效果.md)。

## 4. 与既有验证的关系

本设计不替代、不重排任何既有验收。A1–A5 工程队列与两机验收照旧；评测任务集只在需要向外部说明 AI 编码效果时使用。评测任务执行时走的仍是既有受控链路（独立工作树、审批、真实测试节点），不新增特权路径。
