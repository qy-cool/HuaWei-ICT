# 可量化效果（赛事材料）

2026-11-26。本文面向初赛五要素中「可量化效果」做视角组织。**已实测数字的唯一权威来源是[产品定位第 6 节](../intro/product-positioning.md)，本文不另写一套数字**，只做三件事：按评委关注点重组证据、定义 AI 效果指标的采集口径、给出评测记录的落档模板。

## 1. 已实测证据的分组（引用，非复述）

产品定位第 6 节的全部数字按以下三个维度可用：

| 维度 | 回答的问题 | 对应证据（见产品定位第 6 节） |
|---|---|---|
| 可靠性 | 平台自身的工程质量是否可信 | 943 项后端测试通过（2026-11-19 全量回归，0 失败/错误/跳过） |
| 幂等性 | 重复请求/断线重连会不会造成重复执行或重复效果 | 两机丢终态回执、强杀中控 JVM 后仍只执行一次；订单消费者按事件 ID 去重（重复投递收到确认但库内不增） |
| 恢复性 | 出了问题多久能回到健康状态、数据边界在哪 | 控制面备份及恢复 3.31 秒（2026-11-12、V1–V50、独立 MySQL 8.4.9 范围）并能检出被篡改的备份；PostgreSQL 基础备份 + WAL 连续归档 + 命名恢复点的事务边界实测；同摘要制品测试→生产提升、坏版本自动恢复、显式回滚均有双机记录 |

引用时的强制口径（与决策笔记一致）：

- 3.31 秒必须带范围限定（V1–V50、独立 MySQL 8.4.9、备份及恢复演练），**不是当前 V53 的恢复时间指标**。
- 所有数字写明记录日期；DevSpace 现场版本与 Compose 基线不同时不得混写。

## 2. AI 效果指标（口径定义，待采集）

以下指标**尚无实测数值**。真实模型端点接入（当前未接入，见[部署与基础设施选项](../tech-summary/deployment-options.md)）并按[数据集与评测设计](数据集与评测设计.md)（提案稿）执行任务集后，才能采集：

| 指标 | 口径 | 现状 |
|---|---|---|
| 任务完成率 | 终态为可审查补丁的任务占比 | 待采集 |
| 测试通过率 | AI 补丁在真实测试节点的通过比例 | 待采集 |
| 人工干预次数 | 任务创建到终态的审批与修正次数 | 待采集 |
| token 用量 | 每任务模型调用消耗 | 待采集 |
| 首次可合并时间 | 任务创建到补丁可合入 PR 的时长 | 待采集 |

在真实端点接入前，材料中不得出现以上任何指标的数值估计。回环模型只用于链路确定性回归，不产出效果结论（见[编码任务端到端验收](../logs/20261112-编码任务端到端验收.md)）。

## 3. 评测记录落档模板

每次评测执行后，在 `docs/logs/` 新建 `YYYYMMDD-AI编码评测.md`，至少包含：

1. 版本与端点：平台提交 SHA、模型端点类型与型号（脱敏）、是否回环
2. 任务集：引用当日生效的任务集版本（数据集设计定稿后的版本号）
3. 每任务记录：需求、基准提交、补丁摘要、测试报告位置、审批次数、token 用量、终态
4. 汇总：第 2 节五项指标的当次数值
5. 清理：临时实例与凭据的处理情况

记录完成后回填本文第 2 节表格的「现状」列，并同步到[产品定位](../intro/product-positioning.md)（若数字进入主线口径）。
