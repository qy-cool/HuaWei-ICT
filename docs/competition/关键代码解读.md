2026-11-26。本文讲解四段架构承重代码，全部标注真实文件与行号（基于 `preview@b77c384`），创新点正本见[创新性](../tech-summary/innovation.md)。讲解目的是支撑材料评审与答辩，不改变代码本身；行号随代码演进会漂移，引用时以函数名为准、行号为辅。

## 1. 仓库绑定代次与提交快照（对应 C3）

文件：`server/src/main/java/cloide/server/module/repository/SourceIdentityService.java`（287 行）

关键位置：

- L134–135：L134 抛出 `BusinessException(ErrorCode.SOURCE_COMMIT_MOVED, ...)`，携带当前实际 SHA 的 `Map.of("ref",ref,"currentCommitSha",commitSha)` 在 L135（业务码 40907）。客户端拿到后可直接重读再显式接受，而不是笼统失败。
- L147：`repositories.lockActiveGeneration(project, remoteId, generation)` ——落库短事务内复核并锁定绑定代次。这是 2026-11-18 修复的核心（PR #10）：GitHub 解析期间若发生解绑重绑，旧请求在此处被拒绝（40400），快照表与幂等账本都不写入；调用方用同一请求号重试即可取得新绑定的快照。
- L151：快照 INSERT ——把「ref → 40 位提交 SHA → 树 SHA」连同绑定代次、策略版本一并钉住。此后 AI 与测试作业引用的都是不可变快照，而不是会移动的分支名。

一段话讲解：这段代码把「AI 基于哪个版本的代码工作」从一次性分支名变成一义、可审计、防 TOCTOU 的记录——代次锁在事务内复核，分支前移显式冲突并给出当前值，跨项目访问一律 404。配套验收见[快照绑定代次复核验证](../logs/20261118-快照绑定代次复核验证.md)。

## 2. 节点源码同步执行器（A2）

文件：`agent/internal/syncs/executor.go`（309 行）

关键函数链：

- L57 `Execute`：同步任务入口。领取短期授权 → 下载 → 校验 → 安装，全程进度回报。
- L105 `download`：bundle 下载，支持 Range 续传；每次续传都重新核验授权与期限。
- L131 `claim`：向中控领取绑定代次与有效期限的短期授权——节点不持有长期 Git 凭据，撤权即时生效。
- L237 `verifyBundle`：`rev-parse` 级核验——安装前确认 bundle 展开后的提交与树和快照声明逐字节一致，并拒绝指向后代或无关历史的 ref。
- L263 `install`：staging 目录核验通过后原子更名到最终位置，中断不会留下半成品。

一段话讲解：空节点接入不再依赖管理员预先手工准备 Git 对象库；中控按快照 fetch 并打成受管 bundle，节点凭短期授权取回、rev-parse 核验、原子安装。「节点实际执行的 SHA」从流程上可证明，而不是被声明。配套验收见[空节点首次源码同步验证](../logs/20261120-空节点首次源码同步验证.md)。

## 3. 签名制品发布链（对应 C5）

文件：`deploy/release/node.py`（278 行，发布节点执行器）

关键位置：

- L150-161：制品下载时逐块累积摘要（`digest.update(chunk)` 在 L157），流式写盘并与发布申请声明的 SHA-256 全量比对（L161 `if digest.hexdigest() != sha:`）——坏包在解包前就被拦截；L155-156 同时拦截超出节点上限的制品。
- L164-165：`openssl dgst -sha256 -verify` 用企业公钥独立验签——签名验证不依赖平台自身通道，密钥由企业独立保管。
- L53 `switch`：版本目录间的切换原语，配合候选启动、探针失败自动恢复与显式回滚。

一段话讲解：发布链的信任不建立在「平台说这个包没问题」上，而建立在摘要比对 + 外部验签 + 版本目录原子切换上；生产提升还要求管理员授权、实际构建来源与测试环境同服务健康记录（见[签名静态制品发布双机验收](../logs/20261112-签名静态制品发布双机验收.md)、[Java订单发布与数据回退验收](../logs/20261112-Java订单发布与数据回退验收.md)）。

## 4. AI 编码任务的权限与审批机制（对应 C1）

文件：`worker/src/task.mjs`、`worker/src/main.mjs`

关键位置：

- `task.mjs` L33-34：`const mode = task.mode ?? "build"` + `policy.modes` 白名单校验——节点策略文件声明本仓库允许的模式（如 `["build","guarded"]`），任务请求越权直接拒绝。注意：底层实现是模式数组 + `confirmFiles` 强制确认清单 + `plan` 只读开关；「三档自主程度」是产品叙事层（见[产品定位](../intro/product-positioning.md)），不是代码里的三值枚举。
- `main.mjs`：`approve` 函数从 L16 起；真正发出审批帧的是 L27 的 `emit(proposal)`（含 `approvalId`、路径与新旧内容摘要）。审批绑定具体变更内容；`decision` 只对该 `approvalId` 生效，换内容即换审批。
- 配套约束（见 [worker README](../../worker/README.md)）：每项目最多 32 个 UTF-8 文件、单文件 64 KiB、拒绝符号链接与越界路径、最多 12 轮、每轮 4096 token 输出预算、15 分钟总时限。

一段话讲解：AI 的每一步写盘都在策略白名单、文件清单与逐次审批的三重约束下；审批不是会话级的「允许」，而是绑定内容摘要的单次授权。配套验收见[编码任务端到端验收](../logs/20261112-编码任务端到端验收.md)。
