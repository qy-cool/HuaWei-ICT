# M2-浏览器云IDE与AI编码工作流

**日期** 2026-11-12　　**预估** 16–26 人周　　**前置依赖** M1 节点能力、项目授权和持久作业。

[返回总体规划](20261112-企业自托管AI软件工程平台总体规划.md)。本表为阶段交付基线，实际进度以版本和开发日志为准。

## 本轮实现进度

云 IDE 在 ARM64 上通过真实编辑、终端测试、休眠、恢复和撤权。Pi、工作树、逐次审批、取消与差异已实测；GitHub App 有本地协议验收，新的订单工程可独立导出。IntelliJ Java PSI 已用于查找具体文件行号，完整工作空间引擎与目标团队仓库仍需单独验证。 [实施与验证记录](../logs/20261112-企业平台实施与验证.md)

## 工作方式

以一个用户的持久卷、一个 AI 任务的独立工作树为边界。网关鉴权 HTTP 与 WebSocket，撤权时关闭连接；源码和模型预算按项目执行。

## 开发任务

- [ ] 接入 GitHub App，以仓库安装权限完成新建、导入、分支、PR 和 webhook 处理。重复 webhook 按事件 ID 去重。[GitHub App 授权机制](https://docs.github.com/en/apps/creating-github-apps/about-creating-github-apps/about-creating-github-apps)
- [x] 交付 Java API 与三个中间件的后端项目模板，包含测试、健康检查、部署清单和本地开发说明。
- [ ] 对已有项目识别模块和构建入口。对不能可靠识别的模块，让用户在导入界面指定；保存后可重复执行。
- [x] 接入 code-server 工作区生命周期。真实浏览器及 ARM 节点覆盖打开、编辑、集成终端、休眠恢复和撤权，停用及卷保留按工作区手册执行。
- [ ] 接入 Pi 会话，完成受控工具、代码差异、取消、断线续看和测试证据收集。
- [ ] 实现 ZCode 式模式选择，覆盖会话创建、任务恢复、子任务继承、权限撤销和审批过期。
- [ ] 用 IntelliJ Standalone Analysis 验证 Java 类、方法和依赖解析，输出可跳转的文件、行号和对应提交。
- [ ] 跑通订单系统需求，同时验收 AI 和开发者并发改同一文件，以及任务期间目标分支已前移的情况。

## 交付与交接

浏览器演示新建和导入两种入口；订单取消需求的代码差异、测试报告、审批记录和 PR 可依次追溯。

## 验收与异常场景

浏览器关闭后继续任务；用户与 AI 同时改同一文件能发现冲突；运行中撤权、模型超时、未提交文件休眠恢复均保留相应证据。

验收记录包含版本、输入、复现步骤、预期和实际结果、恢复动作及环境清理情况。未实测的环境列入待验证项。
