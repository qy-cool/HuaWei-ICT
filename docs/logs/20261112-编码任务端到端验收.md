# 编码任务端到端验收

2026-11-12 在同一台 Windows x86_64 开发机上以随机回环端口启动独立 MySQL 8.4、Java 21 Spring Boot 中控以及企业模型兼容接口夹具。节点使用真实 Pi SDK 1.4.0、Node.js 和 Git。验收程序从空数据目录执行 Flyway、登录、创建项目、兑换一次性节点凭据并分配开发环境，随后经项目 REST API 提交需求和基准 SHA。节点以出站请求领取任务。

两次模型响应触发了 `started → approval → change → text → patch → finished`。审批 API 提交了实际的单次审批 ID，Git 差异包含预期的 `+reviewed`。中控最终状态为 `ready_for_review`，人工检出中的未提交文件保持原样。程序结束时停止节点、模拟模型、Java 和 MySQL，等待子进程退出并删除临时数据目录和凭据。

复现时在 `worker/` 执行 `npm ci --ignore-scripts`，以 Java 21 在 `server/` 执行 Maven Wrapper 的 `package`，然后运行以下命令。MySQL 服务端目录应同时含有 mysqladmin，Linux 上使用能够启动独立 mysqld 的普通测试账户。

```sh
node acceptance/control.mjs /absolute/path/to/server.jar /absolute/path/to/mysqld /absolute/path/to/java
```

[验收程序](../../worker/acceptance/control.mjs) 与[节点接入说明](../../worker/README.md)对应。另行实测 Pi 组件的五个用例，包括计划模式、内容摘要、重复回执、进程间恢复和取消；Java 的三个数据库测试覆盖审批绑定、撤权和租约过期待核实。这里的模型使用确定性回环响应。企业真实模型质量、浏览器编码点击路径和跨机 Pi 工作负载尚需独立验收。

追加企业身份联调时开启 `CLOIDE_TEST_OIDC=1`，空库迁移包含 V45。使用[本地签名 IdP](../../worker/acceptance/oidc.mjs)实际检查授权码、S256 challenge、浏览器 Cookie、签名公钥、issuer、audience、nonce、大小写敏感的 sub 和单次状态。已映射账号成功取得平台 JWT 并访问 `/api/auth/me`。错误浏览器 Cookie、重复回调、错误声明与撤销映射后的企业登录均被拒绝。随后用同一中控重走编码任务，六个预期事件到齐。两项 OIDC 状态测试、三项编码数据测试及十七项原认证服务测试通过。企业身份目录分组同步和实际生产 IdP 互通待独立验证。
