# 浏览器云 IDE 双机验收

2026-11-12 使用一台 Linux x86_64 云中控、独立 MySQL 8.4.10、一个 ARM64 开发节点和本机无头 Microsoft Edge。中控从空库迁移到 V48。ARM 节点验证官方 code-server 4.145.2 归档的 SHA-256 为 `e867a34416e2da4a83496b09580001893e7a4e5bb58a0624c4fcd22819e7d53d`。IDE 位于非 root bubblewrap 沙箱，工作树和 IDE 用户数据使用独立持久目录。测试选择空的只读 procfs 模式。[上游固定版本](https://github.com/coder/code-server/releases/tag/v4.145.2)

| 操作 | 实测结果 |
|---|---|
| 自助注册首管理员、创建项目、兑换节点邀请、分配开发环境、登记受管工作区 | 返回固定工作区 ID 和专用域名，节点认领同一项目和实例后回报 code-server 就绪 |
| 进入 IDE | 兑换一次性票据取得独立域名 Cookie，浏览器经过实际 session-guard 访问官方编辑器并建立 WebSocket |
| 编辑、保存、休眠和恢复 | 在浏览器打开 `acceptance.txt`，修改并保存。在节点上读到了未提交内容。请求休眠并收到实际 sleeping 回执后恢复，使用新会话再次从编辑器读到相同修改 |
| 从集成终端运行项目测试 | 在真实 VS Code 命令面板启动登记的默认测试任务，验收用户明确确认信任这个临时参考仓库。ARM 终端运行 `/bin/sh verify.sh`，核对修改后的文件和环境凭据隔离，实际生成 `workspace-ide-test-ok` |
| 撤销已经打开的工作区 | 移除开发节点分配，观察到两条已建立的 IDE WebSocket 关闭。继续携带原 Cookie 的浏览器同源请求收到 HTTP 401，节点回报 sleeping |
| 兼容及恢复模式 | 五项工作区契约测试通过，覆盖传统登记、单次票据、既有会话撤销、节点代次、过期心跳，以及恢复态只观察 |

测试使用临时 CA 保护节点控制请求，临时 TLS 入口和 SSH 私网映射连接真实 guard、Java 中控和 ARM Unix socket。浏览器使用测试域名解析和临时证书，票据在夹具中通过实际 Java 网关兑换。企业公网 DNS、生产证书、Nginx 入口、大规模工作区配额和通用联网开发环境需要在相应部署拓扑中验证。运行命令、节点配置和工作区持久目录说明见[验收脚本](../../scripts/api-test/run-workspace-e2e.py)与[管理员手册](../../deploy/workspace/README.md)。

最终使用 `--terminal` 的整轮流程退出码为 0。两台机器的临时目录、IDE、数据库、中控和附属进程已退出，另外建立的 ARM 官方归档临时缓存也已删除并确认不存在。
