# 空节点首次源码同步验证

2026-11-20，ycwsjc。基线为 `preview` 的 `ef8cbd2`。改动涉及 Go Agent 的消息路由、开发节点清单和对应回归用例，配置示例见[节点作业协议](../protocol/node-jobs-v1.md)。

## 在空节点取回旧版本

在 Linux x86_64 测试机上用普通用户启动本次分支构建的 Agent。清单声明同步目录和空仓库列表。测试中控在回环地址通过 WebSocket 派发，通过 HTTP 提供测试授权和真实 Git bundle。

| 检查点 | 实际观察 |
|---|---|
| 节点启动 | 节点上报 `repositories: []` 和 `source.sync.v1`，随后接收首条 `source.sync`。原路由会略过这条消息，新增回归在修复前失败。 |
| 指定版本 | 将 `orders.txt` 从 `baseline` 改成 `advanced branch content` 并推进源分支到 `ff082d7`，派发较早的 `7af7851`。在节点最终安装目录按快照引用读取该文件，实际为 `baseline`。 |
| 回执与重试 | `ready` 返回的提交、树和包摘要与派发值相符。确认后重发同一请求得到同一结果，节点只领取一次授权。 |
| 资源回收 | Agent 收到 SIGTERM 后退出。验收结束时测试进程和私有临时目录已清理。 |

这次使用了真实节点进程、Git 和网络协议。中控由测试服务模拟。测试机用一个一旦被调用就会令用例失败的占位程序满足 `bwrap` 的启动检查，本次执行路径仅同步源码。

## 仓库内可复跑的检查

在 `agent/` 执行 `go vet ./...` 和 `go test -count=1 ./...`。两者在 Go 1.23.12 的 macOS ARM64 环境通过。下列用例分别覆盖这次修复的两个入口。

- `go test -count=1 -run '^TestSourceSyncDispatchReachesExecutor$' ./cmd/cloide-agent` 验证首帧进入执行器。该用例与既有真实 Git 安装用例也通过了定向竞态检查。
- `go test -count=1 -run '^TestLoadRunnerAcceptsSourceSyncWithoutRegisteredRepositories$' ./internal/jobs` 验证空清单的能力上报和未登记作业的拒绝行为，已在非 root Linux 上运行通过。
