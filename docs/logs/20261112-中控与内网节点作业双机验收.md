# 中控与内网节点作业双机验收

日期 2026-11-12，操作人 Codex。使用 [双机验收程序](../../scripts/api-test/run-project-jobs-e2e.py) 和 [Linux 夹具](../../scripts/api-test/project-job-fixture.py)，根据[节点作业协议](../protocol/node-jobs-v1.md)测试普通用户入口和最终回执恢复。

| 条件 | 实测 |
|---|---|
| 云中控 | Linux x86_64，Java 21，独立 MySQL Community Server 8.4.10，从空库执行 Flyway 至 V40 |
| 内网节点 | Linux ARM64，非 root Go Agent，bwrap 隔离仓库，实际检出固定 SHA 并运行测试 |
| 访问路径 | 临时回环端口经 SSH 转发，测试代理转发 Agent WebSocket；Redis 和 RabbitMQ 关闭 |
| 数据隔离 | 独立临时数据目录、服务账户凭据、测试项目与 Git 仓库；仓库测试验证环境中无数据库及 Agent 凭据 |

从 REST 注册首管理员并登录，创建测试项目，签发并兑换一次性登记令牌，将节点分配到 test。重复提交同一请求，项目历史只出现一项作业。节点检出指定提交，测试生成一次随机标记并以 0 退出。中控接收结果时，代理丢弃首个 ACK 并断开通道。

重连后收到 2 份完全相同的节点结果，持久执行标记只出现 1 次，REST 详情状态为 `succeeded`，退出码为 0，共 3 个实时日志分段。节点验证过程中没有启动第二次测试。验收程序完成对临时 Go、Java 和 MySQL 子进程的等待与清理，随后通过独立 SSH 查询确认两台临时目录均已删除。

追加浏览器实测：使用本机无头 Edge 加载本次构建的工作台，实际登录并选择节点，填写仓库和提交，从页面启动测试。丢弃首次 ACK 后刷新页面并重新登录，确认同一作业号、成功状态和真实订单测试输出可读。代理共建立两次连接，收到两份终态、一个执行标记和三个日志片段；重复兑换登记令牌被拒绝。该临时客户端已归档；本次交付通过双机验收程序的 REST 入口复跑，前端由项目负责人自行选型。新版 RabbitMQ 唤醒、跨实例高可用和生产发布另行验收。相应后端的 17 项聚焦测试也在 Java 21 下实际通过，其中 5 项覆盖 V39 SQL、去重、撤权、取消、过期及断线回执。
