# 创新性：让企业敢把 AI 纳入软件工程

2026-11-20。本文记录 Cloide 相对通用 AI 编码工具和常规 CI/CD 的工程化差异。每条都标注可验证的证据位置；尚未实测的明确写出。赛事材料如需摘录，见 [docs/competition/innovation.md](../competition/innovation.md)，勿把评分点写成产品必须实现的范围。

## 1. 总论

现有 AI 编码工具（GitHub Copilot、Cursor 等）主要解决「AI 会写代码」；本项目要解决「企业敢让 AI 写代码」。差异不在模型本身的能力，而在**工程化**：权限、审批、幂等、证据链。这四件事是让 AI 从「个人工具」变成「企业生产设施」的承重墙。

## 2. 创新点

### C1 授权收敛的 AI 自主程度模型

- 内容：AI 自主程度分三档（变更前确认/自主模式/完全访问）并另设独立计划模式，授权按「用户 → 项目 → 环境 → 节点/服务 → 动作」逐层收敛；所有入口显式传递模式，缺省回到变更前确认。
- 差异：许多商业工具的权限是「全局开关」；本平台的审批绑定具体变更——一次生产审批绑定制品摘要、目标环境、配置版本与有效期，换包、换节点或改迁移步骤后自动失效重审。
- 证据：编码任务端到端验收（计划开关、三档权限、内容摘要审批、撤权、取消、恢复）见[编码任务端到端验收](../logs/20261112-编码任务端到端验收.md)。

### C2 「AI 说完成」≠「工程完成」的判定闭环

- 内容：AI 报告完成只代表模型结束该轮；平台依据真实 Git 差异、测试进程退出码、测试报告、制品摘要与部署回执判定工程状态。
- 差异：业界普遍以模型回复为终点；本平台把模型输出降级为「待验证声明」。
- 证据：受管节点最终检查目标文件；两机作业验收中「一次实际执行 + 退出码 0」与模型回复解耦，见[中控与内网节点作业双机验收](../logs/20261112-中控与内网节点作业双机验收.md)。

### C3 仓库绑定代次与提交快照（A1）

- 内容：仓库按稳定 remote_id 引入单调递增绑定代次；提交快照钉住 ref → 40 位提交 SHA → 树 SHA。分支前移返回 40907 并携带当前实际 SHA；幂等重放返回原快照；跨项目访问一律 404 不泄露存在性。
- 差异：把「AI 基于哪个版本的代码工作」变成一义、可审计的记录，而不是一次性的分支名。
- 证据：`SourceIdentityTests` 回环验收，以及真实 MySQL 上 `RepositorySourceIdentityMySqlValidationIT`（V51 表结构，2026-11-18 记录 6 项通过），见[快照绑定代次复核验证](../logs/20261118-快照绑定代次复核验证.md)。

### C4 可靠作业协议：丢回执或杀进程后仍只执行一次

- 内容：作业信封 + 持久确认 + 重连对账；节点本地持久账本；同一 ID 同参数查账返回原结果，换参数拒绝；跨 JVM 接管靠共享数据库归属核验。
- 差异：常见远程执行方案（SSH 命令、CI Runner）在回执丢失时面临「重跑还是放弃」的两难；本平台以账本证明唯一执行。
- 证据：两机故意丢终态回执、强杀中控 JVM 后仍一次执行，见[中控跨JVM作业接管](../logs/20261112-中控跨JVM作业接管.md)。

### C5 制品来源与回滚证据链

- 内容：制品绑定提交、来源作业、构建节点与摘要；生产提升要求管理员授权、实际构建来源与测试环境同服务健康记录；坏版本自动恢复，回滚后发布前后的业务数据均可核验。
- 证据：[签名静态制品发布双机验收](../logs/20261112-签名静态制品发布双机验收.md)、[Java订单发布与数据回退验收](../logs/20261112-Java订单发布与数据回退验收.md)。

### C6 中间件恢复的可验证演练

- 内容：PostgreSQL 基础备份 + WAL 连续归档 + 命名恢复点；恢复到新实例后以业务样本读写确认再切换；「备份生成」与「恢复验证成功」是两个独立状态。
- 证据：[实施与验证记录](../logs/20261112-企业平台实施与验证.md)中间件行。

## 3. 待完成（如实标注）

- 项目级模型网关（B1）：当前编码节点从私有文件读模型凭据，尚未按项目代理与预算控制。
- 真实企业 GitHub App、真实模型端点、真实 OIDC IdP 的端到端验收：现为回环或模拟服务，属确定性回归手段，不能代替企业安装验收。
- 管理台 Web 前端：后端按接口交付，演示页面待建；不因材料需要而提前启动 `web/`。

近期优先级仍见现状盘点中的 A1–A5，不因展示或参赛需要改写该队列。

## 4. 对照（写作与评审素材）

| 维度 | 通用 AI 编码工具 | CI/CD 平台 | 本项目 |
|---|---|---|---|
| AI 改码 | 具备 | 通常不具备 | 具备（独立工作树 + 审批） |
| 企业权限/审计 | 通常较弱 | 部分具备 | 逐层收敛 + 审批绑定变更 |
| 作业幂等/对账 | 通常不具备 | 部分具备 | 丢回执后仍唯一执行（已有双机记录） |
| 发布回滚证据链 | 通常不具备 | 部分具备 | 摘要级追溯 + 数据回退验证（已有记录） |
| 中间件恢复演练 | 通常不具备 | 通常不具备 | 已有受控环境实测记录 |
| 自托管数据主权 | 部分具备 | 通常具备 | 企业自托管；云与模型为可选接入 |

## 5. 设计来源与许可

三档自主程度与独立计划模式的交互设计参考 ZCode（Apache-2.0，仅设计参考，未使用其源码，登记见[上游组件](upstream-components.md)）；上表所列工程化机制（审批绑定变更、快照代次、作业账本、证据链）均为本仓库自研，并有对应的双机验收或测试记录。
